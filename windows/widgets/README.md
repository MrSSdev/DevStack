# DevStack Widgets 0.2 - two large native cards

## Current implementation

The owner selected **one large size per widget**, with separate information
surfaces, restrained headings, matching line icons, comfortable spacing and
synchronization at the bottom. This revision stays on **Adaptive Cards 1.5**.
There is no Web Widget, WebView, browser server, CDN, or dependence on a running
Ubuntu web server to draw the cards. Absence of a size menu is now intentional.

- **Ubuntu:** a status surface, environment details, explicit Start / Stop,
  two-click Stop confirmation and Cancel. Pending confirmation replaces the
  details panel instead of pushing controls out of the widget.
- **DevStack:** a status surface and four equal service tiles. Availability
  means Windows HTTPS/TCP connectivity, not authenticated systemctl state.
  The distinction is retained in the compact footer. Unknown != offline.
- **Actions and footer:** native ActionSet inside a bottom-aligned stretch
  container, followed by the smaller synchronization timestamp. No invented
  CSS padding properties or pixel-height spacer images.
- **Icons:** six original high-DPI transparent PNGs, consistent rounded badge
  and line weight; generated by CI and embedded in the cards. The attribution
  header uses actual icons rather than tiny WSL/DEV text.

## Preserved runtime and safety boundaries

The COM identity, definition IDs, activation argument handling, status probes,
visibility cancellation and WSL action handlers are unchanged by this visual
revision. The previous actual-device-tested controls are not rewritten.

Opening Win+W requests fresh status immediately, reusing the last-known content.
The timestamp is the time of the last probe, not a claim of continuous tracking.
Passive refresh must not start Ubuntu. The timer and in-flight status reads are
canceled after the final Deactivate callback. Long-term idle, sleep/resume and
power behavior still need target-machine verification.

Only deliberate WSL-widget actions call `wsl.exe -d Ubuntu-26.04 ...` or
`wsl.exe --terminate Ubuntu-26.04`; Stop requires confirmation. The DevStack
widget never controls Ubuntu or Linux services. Closing Win+W is not a promise
to roll back an already accepted explicit Start/Stop command.

## Project navigation

Native project links point to `https://devstack.test/#/new` and
`https://devstack.test/#/projects`. They are hidden when WSL is off or unknown.
The matching frontend hash-route support exists in PR #2 and still requires
**deployment to the local Linux-hosted DevStack website**. Installing this
MSIX does not update that website. Its normal login/session boundary remains.

## Build and checks

GitHub Actions builds and signs the x64 MSIX. No local .NET SDK is required.
The workflow runs C# tests for offline/online/unknown/busy/confirmation/error
states, COM launch arguments, cancellation and guarded action verbs. It checks
exactly one `Capability` containing exactly one `Size Name="large"` for each
original definition. The old one-Capability/three-Sizes mistake is not retained.

The exact C# payloads are also rendered by Microsoft's Adaptive Cards JS renderer
in Chromium in dark/light configurations at the large widget dimensions.
Automated tests check overflow and the bottom footer. The
`DevStack-Widgets-Preview` artifact contains the payloads, PNGs and layout report.
**These renderer tests do not replace testing in the real Windows Widgets Board.**
They do not prove that every Windows build uses the same HostConfig or that all
native clicks/visibility callbacks behave identically.

## Installation

Download `DevStack-Windows-Widgets-x64` from the successful Actions run. Extract
into `%USERPROFILE%\Downloads\DevStack-Windows-Widgets-x64`, replacing older files.
The included MSIX and public CER must come from the **same run**. A new test signer
is generated per run. Verify it before importing to `LocalMachine\TrustedPeople`;
never import this app signing certificate into the TLS root-CA store.

This build reports package version **0.2.0.0**. Installing test builds with a changed
signer may require replacing the previous test package. Such replacement can
remove pinned widget instances; add Ubuntu and DevStack again as necessary.
No Ubuntu reinstall, hosts-task changes or CA changes are needed.
