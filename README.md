# DevStack

**Local Development Environment Manager** — an open-source personal development manager for **Ubuntu 26.04 LTS on WSL2**. Designed to make Laravel/PHP projects easy to host locally without turning a development laptop into a public hosting server.

> **Status: 0.1 — first working release candidate.** Python and PHP unit tests can be run in CI, but the system installer, Windows trust setup, and real browser-to-WSL workflow require testing on an actual Windows + Ubuntu host. **Do not expose DevStack to a LAN or the Internet.** Review the installer before running it as root. Do not use this software to host untrusted code.

## Features

- Polish responsive dashboard: **React 19, TypeScript, Tailwind CSS 4 and shadcn/ui-style local components**, with a light/dark preference persisted in the root-owned server preferences file (`/var/lib/devstack/ui-preferences.json`, mode `0600`). No browser cookie or localStorage is needed. Theme is shared by browsers accessing the same local installation.
- Real systemd service statuses for Nginx, PHP-FPM 8.5, MariaDB and Redis (no fake sample data). Manual refresh shows a spinner, a success/error message and the last successful refresh time; silent refresh runs every 30 seconds.
- Project wizard: name, folder in `~/projects`, `.test` domain, relative document root (usually `public`), optional MariaDB and **Auto SSL**.
- One database and one limited MariaDB user **per project**; password generated with cryptographic randomness, kept outside the Git repository and shown in the panel only after re-entering its password.
- Project detail page includes a **MariaDB TCP read/write smoke test** (temporary table, no lasting test data) and **protected project deletion**. Removal requires retyping the exact slug; for a managed database it additionally requires explicit consent to irrevocably drop the database and its user. Source files in `~/projects/<slug>` are never deleted by this action. Hosts sync removes the deleted project's managed domain automatically.
- Nginx virtual host and per-project PHP-FPM pool generated by a root-owned, Unix-socket helper with strict operation allowlist.
- **Nginx editor:** the main textarea configures three validated directives **inside the first `location /`**. The complete virtual host is collapsed by default and available under **Pokaż pełną konfigurację → Edytuj**. Advanced changes require re-authentication and may affect only the marked `location /` region; `listen`, SSL, `root`, and PHP settings are protected. Every write performs `nginx -t`, reload and rollback. Free-form directives are deliberately not allowed.
- mkcert-based local HTTPS and **event-driven Windows hosts synchronization**: a one-time elevated Windows task observes `projects.json` changes via WSL inotify and maintains only a dedicated DevStack block in hosts. No periodic polling; CA trust requires explicit one-time confirmation.
- Standalone PHP backend without long-running Node or JavaScript server. Node is needed **only at build time**.
- Optional passwordless mode for a trusted local workstation, enabled only through a deliberate root-only Ubuntu command. Password authentication remains the default; both modes retain HTTPS, strict host checking, and CSRF protection.

## Installation: clean WSL2 workstation

You need: Windows 11 + WSL2 + Ubuntu 26.04, `systemd`, a Linux user with `sudo`, and `~/projects` on ext4. Nginx, PHP-FPM 8.5, MariaDB, Redis, Python and mkcert are installed from official Ubuntu packages by the installer.

**Important:** The installer currently supports a first clean install only and does not handle upgrades/migrations. It does not touch any existing projects or existing database accounts. Review `SECURITY.md` and `scripts/install.sh` before using it.

1. In Ubuntu (not PowerShell, **do not use `/mnt/c` for source files**):

   ```bash
   cd ~/projects
   git clone https://github.com/MrSSdev/DevStack.git devstack-source
   cd devstack-source
   bash scripts/preflight.sh
   python3 -m unittest discover -s tests -v
   php tests/php-security.php
   ```

2. Build React assets **as your ordinary Linux user** with Node.js **24 LTS** (or another compatible maintained LTS). If Node has not been installed in WSL yet, install it first from an official supported source; do not run `npm` through `sudo`.

   ```bash
   node --version
   npm --version
   bash scripts/build-frontend.sh
   ```

3. **Review all system-changing commands**, then install locally:

   ```bash
   sudo nginx -t
   sudo bash scripts/install.sh
   ```

   The installer lets you choose **password login** (recommended, at least 14 bytes) or **passwordless local mode**, which requires typing `DISABLE`. Do not share passwords or store them in Git.

4. In **Windows PowerShell as Administrator**, review and run the one-time bootstrap:

   ```powershell
   $setup = '\\wsl.localhost\Ubuntu-26.04\home\ubuntu\projects\devstack-source\windows\setup-windows.ps1'
   Get-Content -LiteralPath $setup
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
   & $setup
   ```

   Replace `ubuntu` with your Ubuntu login if different. This **explicitly asks once** before adding the WSL mkcert root CA to Windows. Review the printed fingerprint before typing YES. It then installs an elevated event-driven task under `C:\\ProgramData\\DevStack`. No secrets or private CA keys are copied.

5. Open **https://devstack.test** in the Windows browser and sign in (or use local no-password mode). When a project is created, the Windows task sees the state change and updates the managed `.test` domain entries **automatically** without PowerShell prompts or periodic checks. Project deletion/rename are not yet implemented in the panel; the synchronization handles domain additions, removals and changes when the approved project state changes. A new project's webroot is empty until application files are added.

**Existing workstation upgrade:** You do not need to rerun the Linux installer or re-trust your CA. Update the repo, install `scripts/watch-domains.py` to `/opt/devstack/scripts/`, then run `windows/install-hosts-sync.ps1` once in an elevated Windows PowerShell window. Full instructions are in [docs/INSTALL-WINDOWS-WSL.md](docs/INSTALL-WINDOWS-WSL.md).

### Authentication modes (Ubuntu only)

The default is **password required**, and missing or malformed authentication settings fail closed. Passwordless mode is only appropriate on a trusted local workstation. **Anyone who can access the local HTTPS panel can create projects, change Nginx and reveal local database passwords in this mode.** Never expose DevStack on LAN, Internet, shared workstations or untrusted Windows/WSL environments.

Run as the ordinary Linux user with sudo, never in PowerShell:

```bash
sudo php /opt/devstack/scripts/configure-auth.php --status
sudo php /opt/devstack/scripts/configure-auth.php --no-password --i-understand-local-risk
# Re-enable and set a strong password:
sudo php /opt/devstack/scripts/configure-auth.php --password
```

Reloading PHP-FPM is usually unnecessary for the mode file (read on every request), but refresh the browser so it re-checks `/api/session`. The panel's Settings screen shows the current authentication mode; changes require Ubuntu administrator access rather than a browser toggle.

**Recovering from an interrupted v0.1 installation at password setup (step 7/8)**: Do not re-run `install.sh` because it is first-install-only. With the current Git checkout, first update installed application files, then choose your mode:

```bash
cd ~/projects/devstack-source
git pull --ff-only
bash scripts/build-frontend.sh
sudo install -m 0644 -o root -g root backend/security.php /opt/devstack/security.php
sudo install -m 0644 -o root -g root backend/public/index.php /opt/devstack/public/index.php
sudo install -m 0644 -o root -g root scripts/configure-auth.php /opt/devstack/scripts/configure-auth.php
sudo cp -a backend/public/index.html backend/public/assets /opt/devstack/public/
sudo chown -R root:root /opt/devstack/public
sudo chown root:devstackweb /etc/devstack
sudo chmod 0710 /etc/devstack
sudo php /opt/devstack/scripts/configure-auth.php --setup
sudo php-fpm8.5 -t
sudo nginx -t
sudo systemctl daemon-reload
sudo systemctl enable --now nginx php8.5-fpm mariadb redis-server
sudo systemctl reload php8.5-fpm
sudo systemctl reload nginx
sudo systemctl enable --now devstackd
```

Check `systemctl is-active devstackd` and the localhost curl command below. This recovery is only for an installation known to have stopped at the password prompt; do not use it as a generic migration procedure.

### Fixing CSRF errors on an existing WSL installation

If GET refresh works but POST settings changes return `Nieprawidłowy token CSRF`, the initial installer may have put PHP sessions under root-only `/var/lib/devstack/web-sessions`. The web user cannot traverse that directory.

In Ubuntu:

```bash
sudo install -d -m 0700 -o devstackweb -g devstackweb /var/lib/devstack-web/sessions
sudo sed -i 's|/var/lib/devstack/web-sessions|/var/lib/devstack-web/sessions|g' /etc/php/8.5/fpm/pool.d/devstack-manager.conf
sudo php-fpm8.5 -t && sudo systemctl reload php8.5-fpm
```

Close the browser tab and reopen `https://devstack.test` with a hard reload. The browser obtains a new CSRF token for its new persistent session. The authentication mode and existing credentials are unchanged. New installations use the corrected session path automatically.

### Eliminating the light flash on dark-theme page loads

The server renders the saved light/dark choice directly into the initial HTML root class and the browser color scheme **before CSS/React paints**. No inline JavaScript, browser cookie, or localStorage is required. React initializes from the server-provided class instead of assuming light mode.

On an already installed Ubuntu WSL2 DevStack (do not rerun the installer):

```bash
cd ~/projects/devstack-source
git pull --ff-only
php tests/php-security.php
python3 -m unittest discover -s tests -v
bash scripts/build-frontend.sh
sudo install -m 0644 -o root -g root backend/security.php /opt/devstack/security.php
sudo install -m 0644 -o root -g root backend/public/index.php /opt/devstack/public/index.php
sudo install -m 0644 -o root -g root daemon/devstackd.py /opt/devstack/daemon/devstackd.py
sudo cp -a backend/public/index.html backend/public/assets /opt/devstack/public/
sudo chown -R root:root /opt/devstack/public
sudo systemctl restart devstackd
sudo systemctl reload php8.5-fpm
```

Verify the returned HTML already contains the class:

```bash
curl -ksS --noproxy '*' --resolve devstack.test:443:127.0.0.1 https://devstack.test/ | head -n 8
```

The first HTML element must be `<html lang="pl" class="dark">` when dark mode is selected, and `class="light"` otherwise. In Windows, use Ctrl+F5 once to update cached assets, then reload normally and verify there is no bright flash. The local TLS certificate, Nginx virtual host and MariaDB are unchanged.


Then refresh `https://devstack.test` with Ctrl+F5. Check that changing the theme persists after restarting the browser, and that the refresh button shows progress plus an updated timestamp. This update requires no Nginx config, database, CA or auth mode changes. If the helper fails to restart, inspect `sudo journalctl -u devstackd -n 50 --no-pager`.

### Project creation fails: runuser cannot set user id (EPERM)

The root-owned `devstackd` service has `NoNewPrivileges=yes`. In this security context, `runuser -u <developer>` is not able to switch user IDs using its setuid path, so creating a project folder can fail before any PHP/MariaDB/Nginx configuration.

The helper now requests a **short-lived systemd service** with `--uid=<validated developer>`, `--wait`, `--pipe`, and `NoNewPrivileges=yes`. PID 1 applies the selected user identity to `mkdir` before the service is restricted. The privileged helper does not write project files as root, and the main `devstackd` security hardening remains enabled.

Upgrade only the helper in Ubuntu:

```bash
cd ~/projects/devstack-source
git pull --ff-only
python3 -m unittest discover -s tests -v
sudo install -m 0644 -o root -g root daemon/devstackd.py /opt/devstack/daemon/devstackd.py
sudo systemctl restart devstackd
```

Before retrying the creation form, verify the project slug currently in the browser; the UI may automatically generate `devstack-test` from the name "DevStack Test", not `test-devstack`. Check the current project list and any partial folder. Do not manually remove folders, databases or generated configs without checking.

### Project creation returns HTTP 502 (earlier v0.1)

Older builds reloaded `php8.5-fpm` synchronously while the DevStack web request was waiting for a reply. This could reset its FastCGI connection and mask the **real cause of a failed project creation**, including errors during rollback.

The helper now schedules an isolated, delayed `php8.5-fpm` reload (using a transient systemd timer) after returning the API response. Nginx is still validated using `nginx -t`, and failed operations roll back the generated configuration. Any error occurring before the reload is returned normally to the web UI.

**Update an existing installed helper** from Ubuntu, without rerunning the installer:

```bash
cd ~/projects/devstack-source
git pull --ff-only
python3 -m unittest discover -s tests -v
sudo install -m 0644 -o root -g root daemon/devstackd.py /opt/devstack/daemon/devstackd.py
sudo systemctl restart devstackd
```

Do not blindly retry project creation after an HTTP 502. First verify the project list and inspect `/var/lib/devstack/projects.json` **locally as root** (never share its secrets), the generated files in `/etc/nginx/sites-available`, and `sudo journalctl -u devstackd -n 40 --no-pager`. The project slug entered in the form may differ from the folder you expect. Do not delete directories, databases or certificates manually without identifying what was created.

### Project database smoke test and safe deletion

From a project's detail page:
- Click **Sprawdź połączenie, zapis i odczyt MariaDB**. The root helper connects as the project's *limited* database user over TCP to `127.0.0.1:3306`, creates a temporary table, inserts a single value, reads it back and drops the temporary table. It never returns the password, and the temporary table does not persist beyond the connection. A real WSL smoke test is needed in addition to the mocked unit tests.
- To remove a project, use **Usuń projekt z DevStack**, type its exact identifier, and—if MariaDB is enabled—check the separate irreversible database removal warning. This removes managed Nginx configuration, PHP-FPM pool, TLS certificate and DevStack metadata; it **does not delete project files**, which are retained under `~/projects/<slug>`. The Windows hosts listener removes the project's old managed domain when the state file changes.

**Database removal is destructive.** Export any valuable MariaDB data first, for example with a locally reviewed `mariadb-dump` command. DevStack v0.1 does not yet manage backup/restore. A project with a managed database cannot be removed without explicitly approving deletion of that database: this avoids leaving orphaned database accounts and passwords behind. The frontend prevents deletion if the confirmation text is incorrect.

On errors before commit, generated hosting configuration is restored. As with any multi-resource operation involving SQL and filesystem state, a host crash or a partial MariaDB SQL failure can still require manual recovery from backup. Do not use the delete action on important data without a verified backup. Code files remain intact so they can be reattached or moved manually.

## Architecture

```text
Windows browser -- HTTPS / devstack.test --> Nginx (127.0.0.1:443)
                      |                       |
                      |                 static React assets
                      |                       |
                      +--> PHP-FPM pool (devstackweb, non-root)
                                  |
                           Unix socket + SO_PEERCRED
                                  |
                           devstackd (root only)
                          Nginx / MariaDB / mkcert
                                  |
                          /home/<user>/projects/
```

Root-only data resides under `/var/lib/devstack/`, credentials under `/var/lib/devstack/credentials.json` (mode 0600), CA private key under `/var/lib/devstack/ca/rootCA-key.pem` (mode 0600). These **never** belong in the repository. PHP's separate web user can read only the Argon2id hash at `/etc/devstack/auth.hash` via group permissions. The helper accepts only a small JSON-RPC allowlist from the dedicated web UID, not arbitrary shell commands or file paths. Individual project PHP pools run as your development Linux user, so project source is **not isolated from other project source**: use trusted local project code.

## Developing

```bash
cd frontend
npm install
npm run build
cd ..
python3 -m unittest discover -s tests -v
php tests/php-security.php
```

CI on every push/PR: TypeScript + Vite build, Python validations and rollback tests, PHP syntax/session tests, Windows PowerShell syntax check, heuristic tracked-secret guard. Actions run only in GitHub-hosted VMs, with read-only repository token. They **never** touch your workstation.

## Known limitations (v0.1)

- No tested in-place upgrade path. Do not re-run the installer over an existing installation.
- Project deletion now removes managed server resources and (only with explicit confirmation) its database, retaining source files. Automatic database backups/restores and password rotation are not available; make verified backups before deleting real data.
- Event-driven Windows hosts synchronization requires one-time elevated setup under the Windows account owning WSL. The watchdog runs only while that Windows user is logged in; after logon it runs an initial reconciliation. It is not an Internet-facing or remote-agent solution.
- Custom Nginx rules are limited to the validated safe subset; do not paste arbitrary directives.
- The database password is **recoverable and stored root-only as plaintext**, not encrypted at rest. Protect Windows login, WSL VHDX and backups; do not use production credentials.
- mkcert local certificates are for development, not public domains. Renewal is not yet automatic.
- Tests in GitHub Actions are not a substitute for a live end-to-end test on WSL2. Only deploy after reviewing test results and verifying the install on a throwaway project.
